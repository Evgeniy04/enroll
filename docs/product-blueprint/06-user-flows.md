## UF-01 · Первый вход и онбординг специалиста
- **Вход:** лендинг `/` → «Создать страницу записи» → `/login?intent=specialist`.
- **Предусловие:** нет сессии.
- **Шаги:**
  1. Email → «Получить код».
  2. Ввод кода (автоматическая отправка после 6 цифр).
  3. Новый пользователь → `/onboarding`.
  4. Шаг 1 «О вас»: имя, профессия, ссылка `vporu.ru/___` с живой проверкой доступности, часовой пояс.
  5. Шаг 2 «Первая услуга»: название, длительность (пресеты), перерыв, цена.
  6. Шаг 3 «Как вы работаете»: «5/2, 10–19», «2/2, 9–21», «Только выходные», «Настрою сам». Предпросмотр 14 дней.
  7. «Страница готова»: ссылка, «Скопировать», «Поделиться» (Web Share API), «Открыть как клиент».
- **Альтернативы:**
  - «Пропустить» на шагах 2–3 — кабинет с чек-листом «Чтобы открыть запись: добавьте услугу, расписание»;
  - вход с `intent=client` — `/me`.
- **Ошибки:** неверный или истёкший код — на шаге 2 с подсказкой; slug занят — варианты.
- **Результат:** `specialist_profile.booking_enabled = true`, ≥1 услуга, рабочие дни на 14 дней.
- **Проверка успеха:** метрика активации; E2E `e2e/onboarding.spec.ts`; юзабилити ≤ 15 мин.

## UF-02 · Настройка услуг
- **Вход:** кабинет → «Услуги».
- **Шаги:**
  1. «+ Услуга» — боковая панель с формой.
  2. Сохранение — услуга появляется в списке.
  3. Перетаскивание или кнопки задают порядок.
- **Альтернативы:** редактирование, скрытие, архивирование (если есть связи), удаление (если нет).
- **Ошибки:** валидация полей inline. Сетевой сбой — панель остаётся открытой с данными, тост «Не удалось сохранить, повторить».
- **Результат:** услуга доступна в шаблонах и на публичной странице.
- **Проверка:** AC SVC-01; E2E.

## UF-03 · Создание шаблонов дня
- **Вход:** «Расписание → Шаблоны дня».
- **Шаги:**
  1. «+ Шаблон» → название, цвет.
  2. «+ Блок»: услуга, начало, количество. Шкала обновляется мгновенно.
  3. Итог: «09:00–17:00 · 5 окон».
  4. «Сохранить».
- **Ошибки:** пересечение блоков (ошибка на блоке и «Сдвинуть на 13:30»), выход за полночь.
- **Результат:** шаблон доступен как кисть.
- **Проверка:** AC TPL-02; unit-тесты движка.

## UF-04 · Заполнение расписания
- **Вход:** «Расписание → Месяц».
- **Шаги (кисть):**
  1. Выбрать шаблон в палитре.
  2. Кликнуть дни или Shift-выделить диапазон.
  3. Тост «Назначено 8 дней · Вернуть».
- **Шаги (правило):**
  1. «Заполнить по правилу…».
  2. Тип (Период / Дни недели / Смены), диапазон, шаблон, режим.
  3. Предпросмотр в сетке и сводка.
  4. «Применить к N дням».
- **Альтернативы:** «Правка дня» — изменить блоки одного дня. «Горизонт записи» — инлайн-ссылка «изменить».
- **Ошибки:** конфликт с записями — предупреждение (записи сохраняются). Сбой сервера — изменения не применены, сетка откатывается к серверному состоянию.
- **Результат:** окна на публичной странице соответствуют сетке.
- **Проверка:** AC SCH-01, SCH-02; E2E «смены 2/2».

## UF-05 · Публикация и распространение ссылки
- **Вход:** чек-лист в кабинете или блок «Ваша ссылка» в навигации.
- **Шаги:** «Скопировать» / «Поделиться» / «QR-код» (PNG для печати) / «Открыть как клиент».
- **Результат:** клиент открывает `/{slug}`.
- **Проверка:** доля визитов публичных страниц по источникам (H-7).

## UF-06 · Запись клиента по ссылке (ключевой)
- **Вход:** `/{slug}` из соцсети или мессенджера, часто во встроенном браузере.
- **Предусловие:** запись включена, есть окна.
- **Шаги:**
  1. Профиль и услуги. Клик по услуге (или единственная услуга выбрана автоматически) → `/{slug}/book?service=…`.
  2. Лента дней (14 дней, листание); дни без окон приглушены, выходные отмечены. Выбор дня → `&date=2026-10-15`.
  3. Окна, сгруппированные «Утро / День / Вечер». Выбор → `&time=14:30`.
  4. «Продолжить» → контакты: имя, email, телефон (опц.), комментарий, согласие.
  5. «Получить код и записаться»: сервер создаёт hold на 10 минут и отправляет код.
  6. Ввод кода → запись `confirmed`.
  7. «Вы записаны»: детали, «.ics», «Записаться ещё»; письма обеим сторонам.
- **Альтернативы:**
  - клиент уже вошёл — шаг кода пропускается;
  - «Назад» сохраняет выбор (URL);
  - переход по ссылке с параметрами восстанавливает выбор.
- **Ошибки:**
  - окно заняли между шагами 3 и 5 — экран «Это время только что заняли», 3 ближайших окна;
  - hold истёк — повторная проверка;
  - код неверный — повтор;
  - нет окон в горизонте — «Свободного времени пока нет» и контакт специалиста, если указан;
  - запись закрыта — PRF-01.
- **Результат:** активная запись, слот недоступен другим, письма в очереди.
- **Проверка:** воронка (шаг 1 → 7), конверсия ≥ 55 %; E2E «гость записывается»; нагрузочный тест BKG-02.

## UF-07 · Перенос или отмена клиентом
- **Вход:** ссылка «Управлять записью» в письме → `/b/{token}` или `/me`.
- **Шаги (отмена):** детали → «Отменить запись» → подтверждение с необязательной причиной → «Запись отменена» и «Записаться на другое время».
- **Шаги (перенос):** «Перенести» → выбор окна (как UF-06, шаги 2–3) → «Перенести на …» → новая запись, старая отменена атомарно.
- **Ошибки:** срок отмены прошёл — «Изменить запись онлайн уже нельзя. Свяжитесь со специалистом: …». Токен недействителен — 404 без раскрытия деталей.
- **Результат:** окно освобождено или заменено, специалист уведомлён.
- **Проверка:** AC BKG-03, BKG-04.

## UF-08 · Работа с календарём и записью
- **Вход:** `/app` → `/app/calendar` (по умолчанию «День» на телефоне, «Неделя» на desktop).
- **Шаги:**
  1. Навигация по датам.
  2. Клик по записи — боковая панель (desktop) или страница (телефон).
  3. Действия: «Перенести», «Отменить», «Не пришёл»; контакты клиента.
- **Ошибки:** конфликт при переносе — сообщение с временем пересекающейся записи.
- **Результат:** календарь отражает актуальное состояние, клиент уведомлён.
- **Проверка:** AC CAL-01, CAL-02, BKG-05.

## UF-09 · Ручная запись по звонку
- **Вход:** «+ Запись» или клик по пустому месту календаря.
- **Шаги:** услуга → время (подставлено) → клиент (поиск или новый) → «Уведомить клиента письмом» (если есть email) → «Создать».
- **Результат:** запись `source = manual`, клиент в списке клиентов.

## UF-10 · Вход клиента и «Мои записи»
- **Вход:** `/me` или «Мои записи» в шапке публичной страницы.
- **Шаги:** вход по коду → список «Предстоящие / Прошедшие» → действия UF-07, «Записаться снова».
- **Результат:** клиент видит все записи, сделанные с этим email.

## UF-11 · Отпуск или больничный
- **Шаги:** «Расписание → Месяц» → выделить диапазон → «Сделать выходными» → если есть записи: «Оставить записи» или «Отменить и уведомить» (причина обязательна) → подтверждение.
- **Результат:** окна в диапазоне не выдаются; клиенты отменённых записей уведомлены.

## UF-12 · Удаление аккаунта
- **Шаги:** «Настройки → Аккаунт → Удалить аккаунт» → сводка (N будущих записей) → выбор действия с записями → код подтверждения → «Аккаунт удалён» → выход.
- **Результат:** AUTH-04.

## Точки входа и выхода

| Точка входа | Куда ведёт |
|---|---|
| Ссылка специалиста в соцсети | P-10 |
| Письмо «Вы записаны» / напоминание | P-13 |
| Поисковая система по имени специалиста | P-10 (индексируется, если специалист не запретил) |
| Лендинг продукта | P-01 → P-02 |
| QR-код в студии | P-10 |

Выход — закрытие вкладки. Состояние записи хранится в URL и на сервере, незавершённых «черновиков» на сервере нет, кроме hold на 10 минут.
