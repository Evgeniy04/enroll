# 00. Executive summary

## Что это за продукт

**[Вывод]** Прототип `enroll` — это сервис онлайн-записи к **частному специалисту**, который работает сеансами фиксированной длины: мастер маникюра, барбер, инструктор по вождению, тренер, массажист, репетитор. Выводы опираются на моковые данные (`apps/native/src/screens/test-store.ts`: «Мастер по маникюру», «инструктор по вождению», тренер), удалённую таблицу `drivingInstructorProfile` (история коммитов), экранный текст «Запишитесь сейчас. Успейте вовремя.», диаграмму действий и видео.

Ядро идеи **[Факт]** — двусторонний цикл:
1. Специалист описывает **услуги** (длительность + перерыв после), собирает **шаблоны дня** («Стандартный», «Интенсивный», «Короткий», «VIP»; блоки «услуга × время начала × количество») и раскладывает их по **расписанию**. Для раскладки есть инструменты «Периоды», «Недели» и «Смены», а также **ограничение записи** (на N дней вперёд, до даты, без ограничения).
2. Клиент находит специалиста, выбирает услугу и свободное время, подтверждает запись. Обе стороны видят записи в календаре и могут просмотреть, изменить или отменить их.

**[Факт]** Реализован только вход по коду из письма (Better Auth, email OTP). Услуги, шаблоны, расписание и записи существуют лишь в UI на моках, без сервера и хранения. Тестов нет. Подробно — в [01](01-source-audit.md).

## Рекомендуемое направление

**[Решение]** Web-продукт **«Аккурат»** — «личная страница записи для частного специалиста». Он состоит из двух поверхностей:

| Поверхность | Для кого | Суть |
|---|---|---|
| **Публичная страница** `akkurat.ru/{slug}` | Клиент, без регистрации | Услуги → день → время → имя и почта → код → запись. Перенос и отмена — по защищённой ссылке из письма. |
| **Кабинет** `/app` | Специалист | Календарь записей, услуги, шаблоны дня, расписание «кистью» и правилами, горизонт записи, клиенты, настройки. |

Ключевые изменения относительно прототипа:
- **Вместо «Контактов» — ссылка.** Поиск специалиста по username и «заявки» заменены ссылкой, которой специалист делится сам. Это снимает лишний шаг и вопрос «как клиент попадает к специалисту».
- **Клиенту не нужен аккаунт.** Запись подтверждается кодом из письма, аккаунт опционален.
- **Модалки становятся рабочими поверхностями.** Расписание показано месячной сеткой, которую заполняют кистью шаблонов. Правила заполнения показывают предпросмотр до применения. Шаблон дня отображается шкалой времени с проверкой пересечений.
- **Серверная правда о доступности.** Свободные окна вычисляет сервер, двойная запись невозможна на уровне БД (exclusion constraint).
- **Данные хранятся в РФ.** Это требование 152-ФЗ о локализации, ч. 5 ст. 18.

## Бренд и название

- **Рекомендация: «Аккурат»** (латиницей — только в домене `akkurat`). Разговорное «ровно, точно» («аккурат в три»): точность времени и аккуратность мастера в одном слове. Оценка ≈ 3,7 из 5; сервисов записи с таким названием не найдено. Первый кандидат «Аккурат» отклонён владельцем из-за созвучия с грубым выражением (§7 [11](11-naming-research.md)).
- **Альтернативы** второго раунда: «Как раз», «Заодно», «Сподручно» (не проверены глубоко); «Точно» отклонён из-за сходства с банком «Точка».
- Прямое использование фамилии («Аврамов. Запись») оценено в 2,55 и не рекомендуется как основной бренд. Допустима авторская подпись.
- **Правовой статус:** проверка по базам Роспатента и ФИПС **не выполнена** — из среды исследования ресурсы недоступны. Уровень риска предварительный. Перед регистрацией домена и публичным запуском нужна профессиональная проверка, см. [12](12-naming-legal-review.md).

## Технологии и архитектура

**[Решение]** Модульный монолит на **TypeScript + React**, итоговый стек согласован с владельцем 11.10.2026 ([13](13-architecture-options.md) §0):
- **Node.js 26**, фреймворк **Next.js 16** (App Router; Server Components для публичных страниц, TanStack Query в кабинете) — единственный веб-процесс;
- API на **oRPC**: типизированные вызовы для своего фронтенда, REST + OpenAPI для публичной части;
- **PostgreSQL** и Drizzle; фоновая очередь pg-boss в отдельном процессе;
- аутентификация по коду из письма — **Better Auth** (фиксированная версия);
- компоненты — **React Aria Components** + Tailwind v4;
- ESLint + Prettier; хостинг **без привязки к провайдеру**: контейнеры на VM (Kamal 2), стандартные PostgreSQL, S3 и SMTP, свои секреты и мониторинг; стартовый провайдер — Selectel.

Обоснование и сравнение — в [13](13-architecture-options.md), схема — в [14](14-architecture.md).

## Состав MVP

В MVP входят:
- вход и онбординг специалиста, публичный профиль;
- услуги, шаблоны дня и расписание (кисть и правила), горизонт и минимальное время до записи;
- расчёт окон и гостевая запись с кодом;
- перенос и отмена по ссылке, календарь специалиста (день/неделя/список), ручная запись;
- автосписок клиентов;
- письма: подтверждение, напоминание за 24 часа, изменения; .ics;
- согласие на обработку ПД и политика; тёмная тема.

**Отложено:** SMS и Telegram, предоплата (54-ФЗ), салоны и команды, отзывы, каталог, синхронизация с внешними календарями. Подробнее — в [05](05-mvp-scope.md).
