# 08. UX-спецификация

## 1. Принципы UX

| # | Принцип | Как проявляется | Проверка |
|---|---|---|---|
| 1 | **Показывай только возможное** | Клиент видит только реально свободные окна. Недоступное приглушено и подписано причиной («выходной», «занято»), а не скрыто без объяснения | Нет 409 `slot_taken` в норме (< 1 % попыток) |
| 2 | **Одно решение на экран** у клиента | Шаги «Услуга → Время → Контакты»; на телефоне одна главная кнопка внизу | Конверсия по шагам |
| 3 | **Думай днями, а не слотами** (специалист) | Шаблоны дня, кисть, правила с предпросмотром | H-2 |
| 4 | **Безопасные действия, обратимые изменения** | «Вернуть» в тосте вместо лишних подтверждений. Подтверждение — только для необратимого и затрагивающего других людей (отмена записи, удаление аккаунта) | Нет жалоб на «случайные» изменения |
| 5 | **Состояние в URL** | Обновление страницы и «Назад» не теряют выбор | E2E |
| 6 | **Говорим как человек** | Короткие фразы, «вы», без канцелярита и восклицаний. Числа с правильной плюрализацией | Ревью текстов |
| 7 | **Доступно по умолчанию** | WCAG 2.2 AA, клавиатура, скринридеры | §9 |

## 2. Визуальная иерархия и композиция

- На каждом экране **одна главная кнопка** (filled accent). Вторичные — outline, третичные — текстовые.
- Порядок чтения: заголовок раздела → ключевой объект (день, запись) → действия.
- В кабинете на desktop: **список или сетка слева, детали справа** (master–detail), без модалок поверх модалок. Модальные диалоги — только для подтверждений и коротких форм (≤ 4 полей).
- На публичной странице бренд специалиста (фото, имя) важнее бренда продукта: логотип продукта в шапке — 20 px.
- Плотность: публичная поверхность «просторная» (базовый шаг 8, секции 32–48), кабинет «рабочая» (шаг 4–8, строки таблиц 44–48).

## 3. Навигационные паттерны

| Паттерн | Где | Почему |
|---|---|---|
| Боковая навигация | Кабинет ≥ 1024 px | Много разделов, постоянный контекст |
| Нижняя панель (4 пункта) | Кабинет < 1024 px | Ежедневное использование одной рукой |
| Линейный мастер с прогрессом | Запись, онбординг | Последовательный сценарий |
| Вкладки-ссылки | Расписание (Месяц, Шаблоны, Исключения) | Соседние представления одного объекта |
| Боковая панель (drawer) | Карточка записи, форма услуги на desktop | Контекст списка сохраняется. На телефоне — отдельная страница |
| Хлебные крошки | Не используются | Глубина ≤ 2 |

Фокус при открытии панели переходит на её заголовок, `Esc` закрывает, фокус возвращается на вызвавший элемент.

## 4. Формы и валидация

- Подписи **над** полем, всегда видимы. Placeholder — только пример, а не подпись.
- Обязательные поля не помечаются, если все поля формы обязательны. Иначе необязательные помечаются «(необязательно)».
- Валидация:
  - при потере фокуса — после первого изменения поля;
  - при отправке — всё сразу, фокус на первую ошибку, сводка ошибок вверху формы при ≥ 3 ошибках.
- Сообщение об ошибке под полем, с иконкой и текстом, связано через `aria-describedby`; поле получает `aria-invalid="true"`.
- Тексты ошибок говорят, как исправить: «Не меньше 5 минут», а не «Неверное значение».
- Клавиатура: `type="email"`, `inputmode="numeric"` и `autocomplete="one-time-code"` для кода, `autocomplete="name|email|tel"`.
- Числа с шагом — поле и кнопки −/+ (44×44) и пресеты-чипы, как в прототипе.
- Время — поле `HH:MM` с маской и выпадающим списком с шагом 5 мин; нативный барабан на мобильных допускается.
- Схемы валидации клиента и сервера — одни и те же (Zod из `contracts`).

## 5. Обратная связь и системные сообщения

| Тип | Компонент | Поведение |
|---|---|---|
| Успех обратимого действия | Тост внизу (снизу по центру на телефоне, снизу справа на desktop) | 6 с, «Вернуть» продлевает до 10 с, `role="status"`, не перекрывает главную кнопку |
| Ошибка действия | Тост с «Повторить» или inline-сообщение | `role="alert"`, не исчезает автоматически |
| Ошибка загрузки | Inline-блок на месте контента | «Повторить», данные из кэша остаются, если есть |
| Предупреждение о последствиях | Inline-баннер attention в форме или диалоге | Перед действием, с конкретикой («в 2 днях есть записи») |
| Подтверждение необратимого | Диалог | Глагол на кнопке («Отменить запись»), а не «ОК» |
| Сеть недоступна | Полоса сверху | «Нет соединения. Изменения не сохраняются», кнопки сохранения неактивны |

Дружелюбные тосты из прототипа допустимы только для несущественных событий (смена темы), но не для ошибок.

## 6. Отображение данных

- **Время:** 24-часовой формат `09:00`, цифры `tabular-nums`. Диапазон через короткое тире без пробелов: `09:00–10:30`.
- **Даты:** «ср, 15 октября»; в пределах ±1 дня — «сегодня», «завтра». Год показывается, если не текущий.
- **Длительность:** «45 мин», «1 ч 30 мин».
- **Деньги:** «2 200 ₽» с неразрывным пробелом; «от 2 000 ₽».
- **Плюрализация:** ICU (`{n, plural, one {# окно} few {# окна} many {# окон}}`).
- **Часовой пояс:** под выбором времени «Время указано по Москве (UTC+3)», если пояс браузера отличается от пояса специалиста. Кнопка «Показать по моему времени» — Next.
- **Статусы записей:** цвет, иконка и текст ([09](09-design-specification.md) §6). Цвет никогда не единственный носитель смысла.
- **Пустые и нулевые значения:** «—» в таблицах, «Перерыва нет» в услугах (вместо «отсутствует» из прототипа).

## 7. Поведение при ошибках (каталог)

| Ситуация | Что видит пользователь | Технически |
|---|---|---|
| Окно заняли | «Это время только что заняли. Ближайшие свободные: …» + 3 кнопки | 409 `slot_taken` и `alternatives` |
| Код неверный | «Код не подходит. Осталось попыток: 3» | 400 `otp_invalid` |
| Код истёк | «Срок действия кода истёк» + «Отправить новый» | 400 `otp_expired` |
| Слишком часто | «Повторите через 45 с» с таймером | 429 и `Retry-After` |
| Сессия истекла в кабинете | Диалог «Войдите снова», после входа возврат с сохранением несохранённой формы (draft в sessionStorage) | 401 |
| Нет прав | 404 для чужих ресурсов | IDOR-защита |
| Сервер 5xx | «Что-то пошло не так. Мы уже знаем. Повторить» + код ошибки для поддержки | `request_id` в ответе |
| Изменение устарело (кто-то изменил раньше) | «Запись изменилась. Обновить» | 409 `version_conflict` (оптимистичная блокировка) |

## 9. Доступность (WCAG 2.2 AA)

| Критерий | Реализация | Проверка |
|---|---|---|
| 1.4.3 Контраст текста | ≥ 4.5:1 (≥ 3:1 для ≥ 24 px или 18,66 px bold). Токены подобраны с запасом ([09](09-design-specification.md) §2) | Автотест контраста токенов в CI |
| 1.4.11 Контраст UI | Границы полей `#7A8581` (3,8:1), фокус 3:1 | Ручной аудит |
| 1.4.1 Цвет | Статусы и шаблоны: цвет, текст или код, иконка, штрих | Ревью |
| 1.4.10 Reflow | 320 px без горизонтальной прокрутки страницы. Календарь недели прокручивается внутри своей области | E2E на 320 px |
| 2.1.1 Клавиатура | Всё доступно с клавиатуры. Сетка месяца и календарь — паттерн grid (стрелки, Home/End, PageUp/PageDown — месяц) | Ручной тест |
| 2.4.7, 2.4.11 Фокус видим и не перекрыт | Обводка 3 px `ink` с отступом 2 px. Закреплённые нижние панели не перекрывают фокус (scroll-padding) | Ручной тест |
| 2.5.7 Перетаскивание | Любое drag-действие (порядок услуг, перенос записи) имеет альтернативу кнопками | Ревью |
| 2.5.8 Размер цели | ≥ 24×24 px обязательно; продуктовая норма — 44×44 | Ревью |
| 3.3.7 Повторный ввод | Контакты клиента не запрашиваются дважды; автозаполнение | E2E |
| 3.3.8 Доступная аутентификация | Код из письма с вставкой (`one-time-code`), без капчи-головоломки на первом шаге. Капча — только при подозрительной активности и с альтернативой | Ревью |
| 4.1.3 Сообщения о статусе | Тосты `role="status"` и `alert`, обновление числа окон — `aria-live="polite"` | NVDA, VoiceOver |
| Язык | `lang="ru"` | — |
| Движение | `prefers-reduced-motion`: без анимаций переходов | — |

Сценарии ручного аудита: UF-01, UF-04, UF-06, UF-07, UF-08 на NVDA + Firefox и VoiceOver + Safari iOS.
