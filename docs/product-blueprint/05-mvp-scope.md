# 05. Состав MVP

## 1. Цель MVP

Проверить главную гипотезу продукта: **соло-специалист за ≤ 15 минут публикует страницу записи, и его клиенты записываются по ссылке сами**. Сопутствующие гипотезы — H-1 (гостевая запись), H-2 (шаблоны и кисть), H-3 (email как канал).

## 2. Входит в MVP

| Блок | Требования | Зачем в первом выпуске |
|---|---|---|
| Вход и аккаунт | AUTH-01…04 | Без входа нет кабинета; удаление — обязанность по 152-ФЗ |
| Профиль и ссылка | PRF-01, PRF-02 | Это «продукт» для клиента |
| Услуги | SVC-01, SVC-02 | Основа окон |
| Шаблоны и расписание | TPL-01, TPL-02, SCH-01…05 | Ключевое отличие и источник окон |
| Окна и запись | AVL-01, BKG-01…07 | Главная ценность |
| Календарь и клиенты | CAL-01, CAL-02, CLI-01 | Ежедневная работа специалиста |
| Клиентский кабинет | ME-01 | Перенос и отмена без письма |
| Уведомления | NTF-01…04 | Без подтверждений и напоминаний запись не заслуживает доверия |
| Настройки и право | SET-01, LEG-01…03 | Тема и юридический минимум |
| Нефункциональные | все NFR | — |

## 3. Не входит и почему

| Отложено | Версия | Причина |
|---|---|---|
| Ручное подтверждение записей (BKG-08) | Next | Усложняет поток; статус в модели заложен |
| Telegram, SMS (NTF-05, NTF-06) | Next | Зависит от H-3; SMS стоят денег |
| Заметки о клиенте (CLI-02) | Next | Риск специальных категорий ПД |
| ICS-фид, подписка на календарь | Next | Полезно, но не критично |
| Повторяющиеся записи (BKG-09) | Future | Сложная логика, сегменты S2 и S3 |
| Предоплата (PAY-01) | Future | 54-ФЗ, платёжный провайдер |
| Команды и салоны (TEAM-01) | Future | Другой сегмент |
| Каталог и поиск специалистов (DISC-01) | Future | Требует трафика, меняет позиционирование |
| Нативные мобильные приложения | Future | Web адаптивен; PWA раньше натива |
| Мультиязычность | Future | Аудитория русскоязычная |
| Админ-панель оператора | Next | В MVP — SQL-доступ по регламенту и журнал |

## 4. Что сознательно убрано из прототипа

| Функция прототипа | Решение | Обоснование |
|---|---|---|
| «Контакты» с поиском специалиста по username | Убрано | Клиенту неоткуда знать username; ссылку даёт специалист |
| «Отправить заявку» в контакты | Убрано | Сценарий не определён, нет ценности для записи |
| Удаление контакта | Заменено | «Мои специалисты» появятся в ME-01 как история |
| Звонок специалисту как способ записи | Оставлен как вторичный | Кнопка телефона в профиле, если специалист его указал |
| Вход по телефону | Отложено | SMS-провайдер и стоимость; email достаточен для MVP |
| Отдельная «регистрация» | Объединена с входом | OTP |

## 5. Границы качества MVP

MVP выпускается, только если выполнены условия готовности ([18](18-testing-strategy.md) §8):
- все AC требований MVP проходят;
- нет открытых дефектов уровней S1 и S2;
- WCAG 2.2 AA подтверждён на ключевых сценариях;
- данные в РФ, политика и согласие опубликованы, уведомление в РКН подано (если требуется для формы владельца);
- резервное копирование проверено восстановлением.

## 6. Пилот

- 10–20 специалистов сегментов S1 и S2, найденных через сообщества мастеров и знакомых владельца.
- Длительность — 6 недель. Еженедельные интервью с 3–5 участниками.
- Решение после пилота — по метрикам [02](02-product-vision.md) §10 и гипотезам H-1…H-6.
